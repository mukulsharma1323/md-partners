# Mobile backend integration

`src/api/config.js` uses the same deployed API URL as the reference md-tracker web app. Login/catalog use the existing backend routes. Prescription search adds a backend extraction endpoint and native upload pickers; see [prescription-search.md](prescription-search.md).

- Login: `POST /login` with `{ email, password, sessionMeta }`, followed by authenticated `GET /user`. The username field takes the existing account email because the backend authenticates by email.
- Catalog: authenticated `GET /products?page=1&limit=20&search=...`, using `data` and `meta.hasNextPage`. Stock/Medicines and the default Billing view show live products, search, pagination, prices and images. Empty/error/loading states and retry/refresh are included.
- Logout: `POST /logout`; local session and demo state clear even if the server is unavailable. A 401 clears authentication; a 403 displays the permission error.
- Access tokens remain in memory, so restarting the app still requires tapping Login. The Login screen's **Remember me** checkbox is checked by default. After a successful login it stores the account email and password in the device's iOS Keychain or Android Keystore through `react-native-keychain`; next launch fills both fields. Unchecking removes the saved credentials immediately. Logout clears the session but leaves remembered credentials until the user unchecks the box. The Keychain service uses device-only, non-iCloud-synced storage. Native app rebuilds are required after adding the package.
- Store data: authenticated `GET /pharmacy/bootstrap?sections=reference,catalog,crm,inventory,purchases,sales` supplies customers, suppliers, batches, purchases and retail invoices. Wholesale orders and wholesale invoices are excluded from the mobile sales list. Stock is calculated from pack quantity and loose units, and the earliest eligible batch is selected for billing.
- Retail checkout: `POST /pharmacy/invoices/retail` with customer, payment, discount and batch rows. Each row sends product and batch IDs, unit, price and stock deduction. The cart clears only after the server accepts the invoice. The app then refreshes store data. Purchase entry uses `POST /pharmacy/purchases`; stock adjustment requests use `POST /pharmacy/inventory/adjustments`.
- Home, stock, sales history, customer bills, supplier history and basic reports read the same live store data. A 20 pack low-stock threshold follows the web app. The backend has no retail return, purchase return, payment collection, shift closing or purchase-order endpoints. Their local demo actions are not exposed in the live navigation.
- Prescription extraction remains connected to `/prescriptions/extract`. A checkout attachment is selected on device for pharmacist review; the retail invoice endpoint has no prescription attachment field, so it is not stored with the invoice.

For a local backend, change `API_URL` to `http://10.0.2.2:3000` for Android emulator, `http://localhost:3000` for iOS simulator, or the Mac's LAN IP for a physical device. Device and backend must be reachable on the same network. Native release builds may require HTTPS or an explicit development-only cleartext configuration.

Manual check: log in with a user authorized for the requested pharmacy sections and retail-sales create permission; check live stock, add a batch-backed medicine, finalize a retail sale, and verify its invoice and reduced stock after refresh. Purchase and stock adjustment mutations require their own backend permissions. Live authenticated verification requires account credentials; no credentials are included in the app or tests.
